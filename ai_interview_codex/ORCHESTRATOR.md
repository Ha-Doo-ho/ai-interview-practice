# 오케스트레이터와 서브에이전트 운영

## 1. 메인의 책임

메인은 요구사항 해석, 저장소 보존, 데이터 계약 확정, 작업 배정, 통합, 실제 검증, 최종 보고를 책임진다. 병렬 작업 수를 늘리는 것 자체가 목표가 아니다. 같은 파일을 여러 에이전트가 동시에 고치게 하지 않는다.

메인 모델은 사용자가 선택한 사용 가능한 모델을 따른다. Astra를 복잡한 계약·통합 검토에, Sol을 범위가 분명한 구현에 배정하는 템플릿을 제공하지만 이것이 품질 보증이나 필수 조합은 아니다. 실제 모델·추론 설정·가용 기능을 확인하고 실행 기록에 남긴다.

## 2. 역할과 소유 범위

| 역할 이름 | 주요 책임 | 기본 수정 범위 | 의존성 |
|---|---|---|---|
| 메인 오케스트레이터 | 정찰, 계약·단계 계획, 통합, 실제 게이트 실행 | 공유 계약·루트 설정·통합 문서; 필요 시 명시적 배정 | 없음 |
| `interview_domain_reviewer` | 좁은 행동 매핑·강도 의미·비교 가능성·보고서 과장 검토 | 읽기 전용; 문제와 수정 제안 반환 | 요구사항, 계약, 이후 변경 diff |
| `interview_backend` | 원본 저장, 버전, 이벤트·기회, API·소유권·삭제·멱등성 | 지정한 서버 경로와 DB 마이그레이션 | 계약 확정 |
| `interview_frontend` | 네 입력, 게임 화면, 면접, 근거 카드·기록 UI | 지정한 UI 경로 | API 타입/예시 확정 |
| `interview_ai_feedback` | 추출/질문/비교·서술 어댑터, 입력 경계, 출력 검증 | 지정한 AI 서비스·스키마·프롬프트 경로 | 서버 인터페이스·소유권 계약 확정 |
| `interview_qa` | 수용 시나리오를 실제 테스트에 연결, 실패 증거 | 지정한 테스트·픽스처·검증 문서 | 해당 서비스 경계 구현 |

표의 경로는 역할 범위다. 실제 파일 경로는 메인이 저장소 정찰 후 정확히 배정한다. 백엔드와 AI 역할이 같은 파일을 필요로 하면 인터페이스를 먼저 분리하거나 순차 작업한다. DB 마이그레이션 소유자는 한 명으로 정한다. QA가 발견한 제품 코드 결함은 담당자에게 전달하며 소유 범위를 침범하지 않는다.

## 3. 작업 흐름

1. 메인이 정찰과 계약 초안을 만든다. 도메인 검토는 읽기 전용으로 병행할 수 있다.
2. 계약/상태/루브릭/매핑 초안을 검토하고 공유 타입을 확정한다. 검토 결과가 없는 매핑은 draft로 유지한다.
3. 서버와 UI의 비중복 파일 작업을 병렬 진행한다. 세 번째 슬롯은 인터페이스가 확정된 AI 어댑터 또는 테스트 설계에 쓴다.
4. 해당 기능이 준비되면 QA가 실제 경계를 호출하는 테스트를 연결한다. 기대 결과를 복사하는 러너는 거부한다.
5. 메인이 통합하고 독립 검토자가 근거·보안·문구를 검토한다. 발견 사항을 수정하고 필요한 검증을 다시 실행한다.

동시에 실행하는 서브에이전트는 최대 3개다. 하위 에이전트가 재귀적으로 팀을 늘리지 않는다. 좁은 작업과 읽을 파일·입력 계약·수정할 파일을 전달한다. 전체 대화 복제가 꼭 필요한 경우가 아니면 작업에 필요한 맥락만 전달한다.

## 4. 위임 메시지 양식

```text
작업 ID:
목표와 완료 조건:
관련 요구사항/시나리오 ID:
반드시 읽을 파일:
입력/출력 계약과 버전:
수정할 수 있는 정확한 파일/디렉터리:
읽기만 가능한 경로:
동시에 다른 에이전트가 작업 중인 범위:
범위 밖 작업과 금지된 추론:
실행할 검증과 외부 API 호출 금지 여부:
반환 형식: 변경 파일, 설계 결정, 실제 명령/결과, 미실행 항목, 위험, 통합 요청
```

에이전트가 권한·계약·파일 충돌을 발견하면 메인에게 알리고 해당 변경을 멈춘다. 관련 없는 사용자 변경은 되돌리지 않는다. 별도 worktree를 쓸 경우 저장소 상태와 실제 분리 가능성을 먼저 확인하고, 필요한 변경만 통합한다. worktree 생성이나 커밋이 항상 가능하다고 가정하지 않는다.

## 5. 진행 상태와 재개

메인은 `docs/ai-interview/CURRENT_STATE.md`에 다음을 유지한다.

- 현재 목표/범위, 실제 저장소/브랜치, 확인한 스택·실행 환경.
- 확정된 계약·매핑·루브릭 버전과 중요한 설계 결정.
- 완료/진행/대기 작업, 파일 소유자, 실제 에이전트·모델 사용 내역.
- 실행한 검증 명령·결과·모드, 미실행 이유, 유료 호출 유무.
- 다음 작업의 정확한 파일·명령, 변경 전 확인할 사항, 실제 차단 요인.

재개 시에는 이 기록과 현재 파일·Git 상태를 대조한다. 오래된 체크포인트를 사실로 가정하거나 완료 작업을 처음부터 다시 만들지 않는다. 서브에이전트가 ‘통과했다’고 보고한 것은 메인 완료 선언을 대신하지 않는다. 핵심 통합 경로는 메인이 실제 결과를 확인한다.

서브에이전트가 지원되지 않는 환경에서는 같은 역할·검토 기준으로 순차 실행한다. 이 경우 에이전트를 띄웠다고 표현하지 않는다. 설정 설치가 필요하다는 이유로 이미 가능한 구현 전체를 중단하지 않는다.
