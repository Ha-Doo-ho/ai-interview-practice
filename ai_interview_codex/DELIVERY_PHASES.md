# 구현 단계와 완료 조건

이 파일은 저장소에 적용할 구현 순서다. 정확한 앱 경로·실행 명령은 현재 저장소를 조사한 뒤 `docs/ai-interview/IMPLEMENTATION_PLAN.md`에 확정한다. 존재하지 않는 파일이나 테스트를 이미 구현된 것으로 나열하지 않는다.

| 단계 | 구현할 것 | 다음 단계로 넘어가기 전에 확인할 것 |
|---|---|---|
| 0. 정찰·설정 | 기존 소스/지침/스택/테스트 확인, 설정 호환성, 파일 소유권 계획 | 기존 변경 보존, 실제 명령 확인, 모르는 사항 기록 |
| 1. 계약 | ID·버전·입력 타입·상태·매핑·루브릭·원본/파생 계보 | 네 형식의 샘플 왕복, 독립 검토, 활성 매핑 근거 |
| 2. 원본 수집 | 네 성향 UI/API, 자체 다중 라운드 게임, 이벤트/기회 저장 | 새로고침·재시도·시간 초과·접근 통제에서도 의미 보존 |
| 3. 기본 면접 | 중립 질문, 텍스트 답변, mock/live 인터페이스, 독립 추출·인용 검증 | 설문 강도 입력이 없는 기본 추출, 실패/미언급 구분 |
| 4. 통합 | 적격성 검사, 예비 비교, 조건부 후속 질문, 근거 카드 | 강도 원문 보존, 출처·수치 일치, 독립/조건부 구분 |
| 5. 기록·견고성 | 조회·삭제, 작업/캐시 무효화, 동시성·멱등성·로그 관리 | 다른 사용자 접근 차단, 삭제 후 재등장 없음 |
| 6. 인수 검증 | 하네스 어댑터·시나리오 매핑·E2E·문서·리뷰 수정 | 실행 결과와 blocked 항목을 구분, 거짓 완성 주장 없음 |
| 후속 | 영상 녹화/전사·수정본·미디어 인용 | 텍스트 MVP 이후 별도 범위와 저장·운영 조건 확정 |

테스트는 마지막에 한꺼번에 붙이지 않는다. 데이터 손실·근거 오염·접근 통제·삭제처럼 중요한 불변식은 해당 기능과 함께 검증한다. 스타일 변경마다 의미 없는 구현 복제 테스트를 만들지 않는다.

## 자체 콘텐츠의 최소 완료 조건

- 네 입력 타입마다 실제 응답을 저장하고 다시 읽는 화면과 서버 경로가 있다.
- B01~B03의 문항·이벤트·면접 연결 이유를 설명하는 자체 정의가 있다. 모든 문항에 매핑을 강제하지 않는다.
- 게임은 연습과 본 라운드를 구분하고 정보 확인·자원 배분·새 정보 이후 수정 기회를 제공한다.
- 기본 질문은 B01~B03을 다루고, 필요한 경우만 확인 질문을 추가한다. 모든 사용자에게 무조건 불일치 질문을 만들지 않는다.
- 통합 보고서에서 원본 응답·게임 조건·인용을 확인하고 삭제할 수 있다.

## 환경과 실제 실행

기존 의존성 관리·테스트 프레임워크를 따른다. 새 저장소에서는 설치 재현이 가능하게 버전/잠금 파일과 실행 방법을 남긴다. MySQL 대상 구현을 SQLite에서만 시험한 뒤 MySQL 검증 완료라고 표시하지 않는다. 테스트 DB가 없으면 통합 검사를 blocked로 남기고 가능한 순수 함수·mock 검사를 실행한다.

프런트엔드만 가짜 데이터를 보여주면 MVP 완료가 아니다. mock AI는 실제 저장·API·소유권·출처 검증 경로를 통과해야 한다. 실 API를 호출하지 않은 경우 그 사실을 최종 보고에 명시한다. 개발 명령은 사용자 OS에 맞게 안내하되 명령을 실행하지 않았으면 실행했다고 하지 않는다.

배포 산출물과 환경변수 예시는 준비할 수 있으나 실제 운영 배포는 현재 명령의 자동 수행 범위가 아니다. 실제 배포나 비용 발생 검사가 필요하면 구체적인 대상·예산·범위를 정한 뒤 기존 승인 범위를 확인한다. 일반적인 로컬 개발·수정은 계속 진행한다.

## 최종 제출물

1. 기존 프로젝트에 통합된 코드·마이그레이션·타입·자체 콘텐츠.
2. 비밀 값 없는 환경변수 예시, 실제 스택의 설치·실행 문서.
3. 수용 시나리오 ID→실제 테스트 파일/이름의 매핑과 실행 결과.
4. 근거가 추적되는 합성 예시 회차와 보고서.
5. `docs/ai-interview/IMPLEMENTATION_PLAN.md`, `CURRENT_STATE.md`, `VERIFICATION.md`.
6. 미완료·미실행 항목과 실제 차단 이유. 사람 검토와 효과성 평가는 자동 테스트 결과와 별도로 표시한다. 텍스트 MVP 구현 검증을 마쳤어도 수동 연구는 `pending_manual`일 수 있으며, 효과성까지 검증했다고 주장하지 않는다.
