# 패키지 작성 시 확인한 사항

확인일: 2026-09-16.

이 기록은 **지시문 패키지의 형식·참조 검사**다. 앱의 수용 테스트 실행 결과가 아니다.

| 검사 | 실제 결과 |
|---|---|
| TOML 파싱 | Python `tomllib`로 6개 파일 파싱 성공 |
| 사용자 정의 역할 | 5개 이름 고유, 필수 역할 필드 존재, 파일명과 역할 이름 일치 |
| 시나리오 JSON | 파싱 성공, 필수 키 존재, 68개 ID 고유·연속 |
| 시나리오 분류 | 자동 검증 대상으로 설계한 사례 66개, 사람 검토 1개, 효과성 평가 1개 |
| 요구사항 참조 | 59개 ID가 정의되고 사용됨, 미정의/미사용 ID 없음 |
| 문서·역할 파일 참조 | 상대 Markdown 링크와 역할 지시문의 패키지 경로 확인 |
| 코드 블록 | Markdown fence 짝 확인 |
| 인용 좌표 예제 | Python 슬라이스와 JavaScript `Array.from`에서 Unicode code point `[8,13)`이 동일한 `물었어요🙂`를 반환 |
| 검토 | 별도 에이전트의 요구사항 검토 후 번호 기준, 기본/조건부 근거, 수동 평가 범위 등의 불일치 수정 |

다음은 수행하지 않았다.

- 사용자의 실제 저장소 수정, 앱 구현, 앱 테스트 실행.
- 사용자의 Codex에 설정 설치, 해당 클라이언트에서 설정 로딩 확인.
- 외부 AI 공급자 호출, 실제 사용자 데이터 분석, 운영 배포.
- 두 사람의 블라인드 평가나 강도 보존의 효과성 연구.

따라서 하네스 실행 상태는 `NOT IMPLEMENTED / NOT RUN`이다. `HARNESS.md`와 `harness/scenarios.json`을 실제 서비스 경계·설정·테스트 결과에 연결하는 작업은 이 명령을 받은 Codex가 수행해야 한다. 실제 설치에서의 설정 지원 여부는 `CODEX_SETUP.md`에 따라 확인한다.
