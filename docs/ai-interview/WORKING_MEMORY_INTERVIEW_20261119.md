# 작업기억 경험 면접 추가 및 게임별 문항 적대적 검토

## 적용 내용

사용자가 승인한 경험 질문 1개와 고정 후속 질문 4개를 텍스트 면접의
**작업기억 경험 면접 · 선택 답변**에 추가했다. 각 문항에 별도 입력·저장·수정·건너뛰기·답변 없음 기록이 있다.

1. 여러 사람에게 받은 요청을 처리하던 중 일부 조건이 바뀐 경험을 설명해 주세요. 처음 요청과 변경된 내용은 무엇이었으며, 최종적으로 어떻게 처리했나요?
2. 그때 동시에 기억해야 했던 정보는 무엇이었나요?
3. 바뀐 조건과 그대로 유지되는 조건을 어떻게 구분했나요?
4. 빠뜨리거나 혼동한 부분은 있었고, 어떻게 확인했나요?
5. 메모나 도구를 사용했다면 어느 단계에서 사용했나요?

직장·학업·일상 경험을 허용한다. 네 후속은 첫 경험과 같은 사례에 답하도록 안내한다.
실제 게임 기록이나 이전 답변 원문을 공개하여 생성한 질문이 아닌 고정 질문이다.
질문 그룹과 부모 질문 ID, 원문, 답변 버전은 저장된다. 게임 결과 공개 후 생성하는 기존 조건부 후속과 구분한다.

- 새 웹 회차(five-game-v2)는 다섯 문항을 자동 포함한다.
- 기존 진행 중 회차는 텍스트 면접의 **이 회차에 작업기억 면접 추가** 버튼으로 추가한다.
- 완료 회차는 수정하지 않는다. 질문이 없으면 새 회차 안내를 표시한다.
- 기존 기본 면접 세 문항과 완료 조건은 그대로다. 새 다섯 문항은 선택 답변이다.
- 서버 저장 원문과 수정 이력을 면접에서 확인하고, 근거 보고서에서는 별도 자기보고로 표시한다.
- 최종 확정 시 최신 답변과 미응답/건너뜀/답변 없음 상태를 보고서에 고정한다.
- 답변은 작업기억 능력 점수나 기존 기본 면접 AI 분석에 포함하지 않는다.
- 새 설문 문항, 다른 게임의 면접 문항, 수행형 작업기억 검사는 이번 요청에서 구현하지 않았다.

## 게임별 기존 문항의 적합성

독립 검토 모델: **GPT-6.2 Astra, reasoning high**. 사용자 요청에 따라 Terra 대신 사용했다.
검토 대상은 실제 app/content.py 정의와 화면·분석·후속 생성 경로다.

| 게임 | 나 알아보기 | 텍스트 면접 | 판정 및 남은 범위 |
|---|---|---|---|
| 가위바위보 | O-B03 새 정보 뒤 계획 재검토 | baseline-b03 선택 유지/변경 경험; B03 조건부 후속은 게임의 규칙 변경 후 응답 기록 포함 | 부분 관련. 자동반응 억제·전환 정확성의 수준을 면접에서 평가하는 기준 없음 |
| 도형 회전 | 전용 문항 없음 | 전용 문항 없음 | 공간 관계·회전·반전의 추론 과정 미포함 |
| 길 만들기 | O-B02 목표·제약을 확인한 시간 배분 | baseline-b02 제한 자원, 대안, 배분 기준, 결과 | 부분 관련. 계획과 대안의 효율을 구분하는 평가 기준 없음 |
| 마법약 만들기 | 확률학습 전용 문항 없음. R-UNMAPPED 학습 기회는 환경 선호 | 공통 배운 점, B03 재검토 경험. 새 작업기억 면접은 정보 유지·갱신에 간접 관련 | 반복 결과에서 규칙 추론·확률적 예측 갱신을 묻는 전용 문항 없음 |

일반적인 경험 설명과 게임에서의 수행능력은 동일한 측정이 아니다.
기존 면접 AI는 상황·역할·정보·행동·이유·결과·배움의 명시 여부를 추출한다.
말을 구체적으로 했다는 사실을 인지력·분석력이 우수하다는 판정으로 바꾸지 않는다.

## 공식 자료와 해석 범위

- [JOBDA 게임별 설명](https://www.jobda.im/info/406): 가위바위보는 유연한 인지·반응제어, 회전은 공간지각, 길은 계획, 마법약은 학습·작업기억, 약속은 작업기억.
- [공식 HR 보고서 인쇄 17쪽](https://recruit.jobda.im/hubfs/TREND%20REPORT_HR%20%EA%B3%A0%EB%AF%BC%EC%9E%88%EC%8A%B5%EB%8B%88%EB%8B%A4_2%ED%8E%B8.pdf#page=17): 가위바위보는 인지력, 회전·길·마법약은 분석력과 연결.
- 약속은 공식 작업기억 설명을 사용한다. 자체 숫자 카드는 규칙 유지·갱신에 작업기억이 관여한다고 설명할 수 있으나, 잡다의 공식 작업기억 분류로 표기하지 않는다. 현재 규칙이 화면에 표시되므로 기억 부담에도 한계가 있다.

## 적대적 구현 검토

초기 변경에서 기존 자원 배분 회차의 두 회귀를 발견했다.
1. 구 분석기가 선택 면접 답변을 기본 면접 추출기에 전달해 실패.
2. 구 정적 화면이 선택 면접을 필수 조건부 후속으로 분류해 분석 단계를 건너뜀.

수정: 구 분석과 변경 감지 입력에서 선택 면접 답변을 제외하고, 구 화면의 조건부 후속 필터를 adaptive_followup으로 제한했다.
Astra가 메모리 내 Python 분석과 JavaScript 진행 함수로 재검증하여 두 문제가 해결됐음을 확인했다.
실제 API의 분석·확정·완료 후 변경 차단 회귀 테스트도 추가했다.

## 확인 방법

서버를 재시작하고 브라우저를 새로고침한다. 새 회차는 게임 완료 후 텍스트 면접에서 다섯 문항을 볼 수 있다.
기존 진행 중 회차는 **이 회차에 작업기억 면접 추가**를 누른다.
실제 브라우저 도구는 세션 충돌 및 연결 불가로 확인하지 못했다.
API 및 합성 DOM 검증의 명령·결과는 VERIFICATION.md에 기록한다.
