# 2026-10-13 전달본 안내

현재 가위바위보·카드 게임을 유지한 텍스트 면접 흐름의 로컬 구현본이다. 실제 AI 코드는 팀원 컴퓨터에 별도로 있으며 이 전달본의 실행 결과에는 외부 AI 호출이 포함되지 않는다. 실제 검증 집계와 한계는 VERIFICATION.md의 2026-10-13 항목을 따른다.

## 화면 사용 순서

1. 실행 후 `http://127.0.0.1:8000/frontend/index.html`에서 로그인한다. 개발 중 열려 있던 화면은 Ctrl+F5로 새 파일을 받는다.
2. 기존 회차를 이어가거나 새 연습을 시작한다. 설문 6문항과 가위바위보·카드 각 3라운드, 기본 면접 3문항을 처리한다. 건너뜀/시간초과/답변 없음은 각 상태로 남으며 내용이 있는 응답으로 바꾸지 않는다.
3. `4. AI 리포트`에서 `저장 근거 보기 · AI 미사용`을 선택하면 실제 서버 원본을 모은 mock 보고서가 저장된다. 실제 AI 버튼은 서버 설정이 준비된 경우에만 사용한다.
4. `근거 연결·후속 질문 만들기`를 누른다. 설문 원문·기본 면접 인용·게임별 라운드의 공개 전후 선택이 연결된다. 과거 보고서가 새 기준에서 오래된 상태이면 3번부터 다시 만들며 원본 설문·게임을 재실행할 필요는 없다.
5. 면접 화면의 조건부 후속 질문에 답변한다. 공개된 근거와 함께 별도로 저장된다. 추가 답변은 선택이며 미응답으로 확정할 수도 있다. 작성만 하고 저장하지 않은 답변이 있으면 최종 확정을 막는다.
6. 리포트에서 `최종 보고서 확정`을 누른다. 완료한 회차는 읽기 전용이다. 원본과 기본 분석을 유지한 채 조건부 답변과 최종 스냅샷을 저장한다.
7. `응시 기록`에서 서버 회차를 다시 열거나 삭제한다. 이 탭은 이제 서버 자료를 사용한다.

## 팀원 PC에서 실행

ZIP을 별도 폴더에 풀어 기존 AI 코드와 비교한다. 기존 팀원 구현을 통째로 덮어쓰지 않는다. Python과 Node를 설치한 환경에서 프로젝트 루트 PowerShell로 실행한다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\tools\start_interview.ps1
```

실행 스크립트는 새 `team-development.db`를 기본으로 사용하며 주소는 127.0.0.1:8000이다. API 키나 기존 사용자 DB는 ZIP에 포함하지 않는다. 스크립트는 live/paid를 비활성화한 로컬 mock 실행이다. AI 통합은 아래 계약과 AI_CONNECTION_SETUP.md를 따라 서버에서 별도로 설정한다.

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m tools.run_checks tests -q
node --test tests/frontend_*.test.cjs
```

## AI 담당자 연결 계약

- 기존 `app/interview_analysis.py`의 검증된 기본 추출 경로를 사용한다. 입력은 중립 질문·해당 답변·행동 정의·루브릭이다. 설문/게임 결과를 이 입력에 추가하지 않는다.
- 모델 출력의 요소 상태와 원문 인용 `[start,end)`은 답변 ID/버전 및 Unicode code point로 대조된다. 키는 서버 환경변수에만 둔다. 실패한 출력은 근거로 저장하지 않는다.
- 실제 AI 분석 저장 뒤 `POST /api/runs/{run_id}/evidence-linkage`를 호출한다. 본문은 `expected_revision`, `idempotency_key` 두 필드다. 응답은 새 revision을 가진 전체 회차다.
- 질문은 `run.evidence_linkage.questions`이며 `run.questions`에도 보존된다. `question_mode=adaptive_followup`, `conditioned_on_prior_evidence=true`, 공개 내용과 생성 근거 참조가 저장된다.
- 기존 `POST /api/runs/{run_id}/answers`로 후속 답변을 저장한다. 질문 원문·버전·공개 정보·근거 참조는 서버 질문에서 복사된다. 이전 기본 분석은 변경되지 않는다.
- `POST /api/runs/{run_id}/interview-finalize`도 revision/key 두 필드를 받는다. 설문 6·게임별 3·기본 면접 3 처리와 최신 연결을 검사해 완료한다. 후속 미응답은 명시 상태로 보존한다.
- 최종 `run.interview_report`에는 기본 cards/surveys/rule_games, evidence_linkage, followup_answers, source_report_id, completion_policy_version이 있다. 기본 분석 원본은 `run.interview_analysis`에 유지한다.
- 재시도는 같은 본문과 멱등키를 사용한다. 원본을 수정했으면 최신 회차/새 분석/새 연결로 진행한다. 다른 사용자 접근, 확정 이후 수정, 삭제 이후 재등장은 허용하지 않는다.

## 해석과 검증의 한계

게임의 분모는 수락된 응답 수이며 고정 관찰 기회 수가 아니다. 규칙 공개 기록 없음과 공개 후 응답 없음은 다르게 표시한다. 카드처럼 두 규칙에 동시에 맞는 선택은 따로 표시한다. 게임을 B01/B02/B03 직접 측정으로 활성화하지 않았다. 합격·성격·진실성·적응력 점수를 만들지 않는다.

실제 팀원 AI 코드 통합, 외부 AI 실행, 실제 브라우저 시각/키보드 검증, MySQL/운영 배포, 사람 평가/효과성 평가는 별도다. 합성 transport와 DOM 검사를 해당 검증의 완료로 보지 않는다. 이번 브라우저 도구는 연결 목록이 비었고 in-app browser도 unavailable이었다.

전달 ZIP은 소스·필수 합성 fixture·루트 인계 문서·선택한 검사 요약만 포함한다. 비밀 값, .venv, SQLite/백업, 사용자 응답 artifacts는 제외한다. ZIP의 PACKAGE_MANIFEST.json으로 각 파일 해시를 대조할 수 있다. `completion-example-20261013.json`은 이번 실제 API 테스트가 생성한 합성 mock 최종 보고서다.
