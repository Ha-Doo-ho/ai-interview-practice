# 추가 게임 3종 구현 결과 · 2026-11-17

## 실행 방법

기존 로컬 서버를 재시작하고 `http://127.0.0.1:8000/#/game`에 접속한다. 로그인한 계정의 진행 중 회차를 선택한 뒤 게임 탭 하단의 **추가 역량 게임 · 선택 연습**에서 게임을 선택한다. 설명 → 연습 1문항 → 본게임/빠른 연습 → 결과 순서다. 최종 확정된 회차에는 새 기록을 추가할 수 없으므로 새 회차를 선택한다.

게임 자체는 Gemini/OpenAI 키나 AI 호출이 필요 없다. AI를 사용하지 않고 실행하려면 프로젝트 루트에서 `.\.venv\Scripts\python.exe -B -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8000`을 사용한다. 이미 해당 포트의 서버가 실행 중이면 먼저 그 서버 창에서 Ctrl+C로 종료한다.

## 분석한 기존 구조와 통합 방식

- FastAPI `app/main.py`, SQLAlchemy/SQLite `app/store.py`의 사용자 소유 회차·revision·멱등성·삭제·완료 후 변경 차단을 재사용했다.
- 기존 `rule_games`의 가위바위보/카드 규칙 게임과 `appointment_games`의 요일/장소/버스는 규칙·문항·점수를 보존했다. 명세의 기존 게임 명칭과 실제 저장 키는 일부 다르므로 이름만으로 교체하지 않았다.
- HTML/CSS/JavaScript 화면과 `AstraPractice` 구독/회차 갱신/잠금 체계를 확장했다. 새 게임은 기존 다섯 게임과 별도로 선택하는 추가 연습이다. 새 게임 실행 중에는 기존 게임 영역을 숨기고, 완료/중단하면 복원한다.
- 게임 결과는 게임 화면과 AI 리포트 탭에 별도로 표시한다. 면접 AI에 새 게임을 자동 전송하지 않으며, 기존 5게임 AI 계약을 임의로 바꾸지 않았다.

## 규칙과 배점

| 게임 | 자체 기본값 | 구현 |
|---|---|---|
| 도형 회전하기 | 10문항, 전체 240초, 문항당 20회, 만점 100 | 45도 좌우 회전/좌우·상하 반전. 본게임 중 변환 결과 비공개, 연습에서만 미리보기. 실행 취소/초기화도 누적 조작을 되돌리지 않음. BFS로 최소 횟수 계산. |
| 길 만들기 | 10문항, 전체 240초, 문항당 19회, 5×5, 만점 100 | 빈칸→/→\\→빈칸으로 설치·변경·제거. 쉬움 1대/어려움 2대. 공유 울타리·교차 경로 허용, 잘못된 목적지/이탈/반복 상태 실패. |
| 마법약 만들기 | 본게임 100문항/만점 1000, 빠른 연습 20문항/만점 200, 문항당 15초 | 4재료 조합의 고정 확률로 예측과 독립적인 결과 생성. 쉬움 3조합/어려움 6조합 반복. 확률·유리한 선택 정보는 해당 진행 중 시도에서 비공개. 종료 후 별도 지표 표시. |

공통 시작 0점, 정답/예측 적중 +10점, 오답/시간 초과 -5점. 매 문항 `max(0, 직전 점수 + 배점)` 적용. 연습 1문항은 0점으로 본게임에서 제외한다. 회전/길의 전체 시간이 끝나면 현재 문항은 시간 초과, 아직 보여주지 않은 문항은 미제시로 기록한다. 미제시를 오답으로 만들지 않는다. 중단 시 현재 문항은 중단, 이후는 미제시이며 중단 자체의 감점은 없다. 점수 환산은 `원점수 / 문항 수에 따른 만점 × 100`이며 백분위가 아니다.

조작 제한에 도달해도 제출은 가능하다. 초과 조작 요청은 서버에서 거절한다. 기록에는 실제 허용된 누적 조작과 한도 도달 여부가 남으며, 거절된 요청을 수행한 행동으로 세지 않는다.

## 저장·상태·지표

`RunRow.snapshot.aptitude_games.attempts[]`에 게임/규칙 버전, 자체 설정 스냅샷, 난수 시드, 시작/종료 시각, 모드·난이도, 문항 원본, 이벤트, 응답, 점수 전후를 저장한다. 사용자/회차 소유권은 부모 회차에서 해석한다. 서버 원본과 공개 응답은 분리하며 진행 중 정답·확률·시드를 숨긴다.

- 회전: 실제 회전/반전 이벤트 수(취소된 조작 포함), 제출한 명령 수, BFS 최소 횟수, 취소/초기화, 한도 도달, 정답 문항의 최소/실제 누적 조작 효율.
- 길: 실제/최소 울타리, 전체 조작·변경·제거, 첫 조작까지 시간, 문항 해결 시간, 각 차량의 도착/실패 사유·좌표 경로.
- 마법약: 예측한 문항을 분모로 한 적중률, 유리한 선택 비율, 조합별 선택 횟수/색상 비율/실제 결과, 초기·후기, 동일 조합에서 이전 관측 결과 이후의 선택 변경 기록. 시간 초과는 실제 예측으로 계산하지 않는다.

새로고침/탭 이동은 서버 시간을 멈추지 않는다. 다시 시작하면 새 시도를 추가하고 이전 시도는 보존한다. 응답 유실 시 sessionStorage에 보관한 동일 요청으로 재확인하여 이중 채점을 막는다. 최종 면접 보고서 확정 시 안전한 추가 게임 결과를 `report.aptitude_games`에 함께 고정한다. 기존 기록 조회·삭제 및 계정 삭제 경로가 함께 적용된다.

## 공식 자료와 자체 설계의 구분

2026-11-17 [JOBDA 공식 전체 설명](https://www.jobda.im/info/406)을 확인했다. 이 페이지에서 45도 회전과 직접 회전 표시를 하지 않는 방식, 90도 경로 전환과 울타리 공유, 네 카드 조합의 확률 예측, 공간지각/계획/학습·작업기억이라는 과제 목적을 확인했다. [도형](https://www.jobda.im/info/336), [길](https://www.jobda.im/info/338), [마법약](https://www.jobda.im/info/339) 개별 공식 페이지는 영상 안내를 제공하며, 영상 전체 내용을 독립적으로 검증했다고 주장하지 않는다.

배점, 문항 수, 시간, 조작 제한, 난이도, 도형/격자 문제, 확률표, 중단 정책, 환산 점수는 프로젝트 자체 설계다. 로고/이미지는 복제하지 않았다. 화면에 표준화된 심리검사 점수가 아니라는 안내를 표시한다.

## 범위와 남은 한계

- 길 만들기는 검증된 쉬움/어려움 기본 판을 회전·반전한다. 임의 복잡도의 무제한 문제 생성은 구현하지 않았다(명세가 허용한 고정 문제 우선 방식). 보드 크기는 5 이상을 지원한다.
- 마법약 분포·도형·경로의 알고리즘 정확성 검사는 수행하지만 사람의 학습능력/심리측정 타당성 검증은 하지 않았다.
- 브라우저는 도형/길 10문항과 마법약 20문항, 연습·새로고침·키보드·시간 초과·중단·재시작·보고서·390px 화면을 확인했다. 마법약 100문항은 자동 API 전체 진행으로 검증했다.
- 새로운 게임의 AI 해석 프롬프트/유료 공급자 호출/운영 배포는 이번 구현 범위에 포함하지 않았다. 새 결과를 기존 면접 AI 분석으로 표시하지 않는다.
- 실행 명령, 실제 테스트 수, 증거 경로와 기존 하네스의 사람 검토 대기는 `VERIFICATION.md`에 기록한다.
