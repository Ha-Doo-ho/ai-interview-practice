# 설문·게임·면접 종합 연습 보고서

## 판단과 공식 출처

사용자 요청은 세 활동의 근거를 종합해 잘한 점·보완점·개선계획을 AI가 작성하게 하는 기능이다. 서로 다른 자료를 비교해 추가 연습을 찾는 것은 타당하지만, 동의형 설문과 자체 게임 점수를 합산하여 성향 강약을 판정할 검증된 채점식은 없다. 면접 답변을 게임 결과에 맞춰 꾸미도록 안내하지 않는다.

공식 출처: https://recruit.jobda.im/hubfs/TREND%20REPORT_HR%20%EA%B3%A0%EB%AF%BC%EC%9E%88%EC%8A%B5%EB%8B%88%EB%8B%A4_2%ED%8E%B8.pdf

- 14쪽 본문: A사 구 역량검사 사례에서 전략성·실행력·조직적합성·관계성을 열거한다. 전체 성향 분류표가 아니다.
- 17쪽 본문: 전략성과 인지력·분석력의 관계, 가위바위보/숫자 누르기/개수 비교하기와 인지력, 길 만들기/도형 회전/마법약과 분석력을 연결한다.
- 19쪽: 속도와 정확도의 균형은 업무 맥락에 따라 달라진다. 반응시간 하나로 성격을 판정할 근거가 아니다.
- 공식 자료는 자체 구현 게임의 규준·합격선·개인 점수 계산식으로 사용하지 않는다. 도표 이미지에만 있는 추가 명칭은 이번에 확인하지 못해 분류에 포함하지 않았다.

## 기능과 사용법

AI 리포트 탭에서 기존 기본 보고서를 만든 다음 **세 활동 종합 피드백**을 사용한다.

1. **종합 평가 프롬프트 확인 · AI 미사용**: 저장 자료로 만든 입력 JSON을 읽고 복사한다. 소유한 회차의 GET이며 AI 호출과 회차 변경이 없다.
2. **종합 근거 저장 · AI 미사용**: 동일 입력을 저장하고 외부 AI 없이 근거 안내를 표시한다. AI 평가인 것처럼 표시하지 않는다.
3. **세 활동 종합 AI 평가 요청**: 기존 공급자 설정과 비용/호출수 한도 안에서 한 번의 종합 요청을 예약한다. 기본 면접 분석과 별도 요청이다.
4. 잘한 점, 보완점과 비교 제한, 개선계획, 확인 질문에서 인용 근거를 펼쳐 원문/집계를 확인한다. 종합 평가 후 기록이 바뀌면 이전 입력 표시와 함께 재요청이 필요하다.
5. 최종 보고서 확정 시 당시 프롬프트와 최신 자료에 해당하는 종합 결과만 고정한다. 이미 완료된 회차는 수정하지 않는다. 과거 완료 회차에 새 고정 프롬프트가 없으면 GET은 보존된 회차 자료를 현재 프롬프트 버전으로 구성한다.

## 입력 범위

- 설문: 제출한 순서형 위치와 레이블, 관점, 양극 선호, 순위, 미응답 상태를 보존. 상상한 타인은 동일 응답자의 자기보고다. 미선택은 싫어함이 아니다.
- 면접: 최신 답변 버전의 원문, 질문 원문, 버전, 본/후속 관계와 그룹, 기본·선택·조건부 구분. 현재 유효한 근거 연결의 후속만 포함하며 폐기된/오래된 후속 원문을 현재 근거로 다시 전송하지 않는다.
- 게임: 가위바위보·자체 숫자 카드·약속 요일/장소/버스·회전·길·마법약. 실행하지 않은 과제는 missing. 추가 게임의 각 시도를 모드·난이도별로 보존하고 연습을 본검사와 합산하지 않는다.
- 규칙전환은 라운드별 규칙·공개 누락·전환 전후 응답수와 정답수. 개별 반응시간을 임의 산출하지 않는다. 약속은 실제 응답 허용 시작에서 수락까지의 평균과 관찰수를 계산하며 시간초과는 평균에서 제외한다.
- 자체 숫자 카드는 규칙 상시 표시로 작업기억 강약의 근거에서 제외하며 공식 숫자 누르기의 분류를 복사하지 않는다.
- 새 설문에는 대안 비교와 반복 업무의 결과 활용 문항이 들어 있다. 공간 배치에 관한 자기보고는 텍스트 면접에서 받는다.

## 분석 경계와 구현

`app/synthesis.py`는 출처, 주제별 연결 문항, 근거 ID와 응답 규칙을 프롬프트에 넣는다. `interview_comparison`에는 고정 면접 7문항의 비교 답안과 문항별 기준이 들어가며, 지원자의 설문·게임·면접 기록은 `evidence`에 들어간다. 예시는 본인이 한 일, 문제, 방법, 확인된 결과를 설명하는 방식을 보여 준다. 답변의 문장 순서나 예시와의 유사도는 평가 기준에서 제외한다. 결과는 확인 가능한 수치나 구체적인 변화로 설명할 수 있다.

모델은 네 섹션에서 피드백 종류, 주제, 근거 ID를 고른다. 면접에서 잘 드러난 부분에는 해당 문항의 기준과 원문 인용을, 보완점에는 해당 기준을 함께 고른다. 아래는 배분 이유를 더 설명하도록 안내하고 마법약 연습을 제안한 응답 예다. 실제 근거 ID는 회차마다 다르다.

공간 배치 문항은 실제 배치와 설치 과정까지 평가한다. 반복 업무 문항은 비교한 이전 결과와 다음 방식을 선택한 기준을 본다. 다음 업무의 결과는 선택 사항으로 처리하며, 확인한 결과가 있다면 개선 계획에서 덧붙일 수 있다고 안내한다.

```json
{
  "strengths": [],
  "gaps": [
    {"finding_type": "interview_answer_gap", "topic_id": "planning", "evidence_ids": ["interview:answer-example"], "criterion_id": "reason", "quote": ""}
  ],
  "practice_plan": [
    {"finding_type": "practice_suggestion", "topic_id": "learning", "evidence_ids": ["game:potion-example"], "criterion_id": "", "quote": ""}
  ],
  "clarifying_questions": []
}
```

보고서의 숫자와 설명은 서버에서 작성한다. 게임별 최신 완료 본게임을 기준으로 하며, 정답·오답·시간 초과 같은 관찰을 인용 근거에서 대조할 수 있다. 길 만들기는 성공한 문제의 울타리 사용량을 따로 표시한다. 마법약은 실제 제조 결과 적중 횟수·점수와 가능성이 더 높은 색을 선택한 횟수·전후반 비율을 표시한다. 마법약의 보완 근거는 가능성이 더 높은 색을 고르지 않은 응답 또는 시간 초과다.

면접 발췌는 최신 답변에 같은 문장 또는 줄이 있는지 검사한다. 답변 전문도 화면에서 펼쳐 읽을 수 있다. 답변 내용의 사실 여부와 선택된 문장의 적절성은 사람이 확인한다. 설문을 게임과 비교할 때는 같은 주제에 연결된 제출 답변을 쓰고, 설문에 답한 업무 습관과 게임에서 수행한 과제의 조건을 설명한다. [Gemini 공식 구조화 출력 안내](https://ai.google.dev/gemini-api/docs/structured-output?hl=ko)

- GET `/api/runs/{run_id}/synthesis-prompt`
- POST `/api/runs/{run_id}/synthesis-analysis`: 소유권·CSRF·예상 revision·멱등키·완료 회차 보호. 기존 AI 예약으로 중복 실행 방지, 변경 중 결과 게시 방지, 비용 한도 공유.
- 기본 AI 분석 입력에는 설문을 새로 섞지 않는다. 종합 요청에만 세 출처를 포함한다.
- 기본 종합 입력 한도는 80,000 보수 추정 단위(UTF-8 바이트 기준)다. `AI_SYNTHESIS_MAX_INPUT_TOKENS`가 우선한다. 별도 값이 없고 `AI_MAX_INPUT_TOKENS`를 사용자가 명시했다면 그 값을 존중한다. `.env.example`에 전용 값을 안내했다.
- 범위를 넘으면 원문을 몰래 잘라 보내지 않고 전송 전 `budget_exceeded`로 거절한다. 기존 공급자와 최대 출력·시간·비용·호출수 제한은 그대로 적용한다.

## 검증

- 새 핵심/API 테스트 10개 통과: 원척도·최신 답변·8종 결측·추가 게임 실제 엔진 시도·practice 분리·현재 후속 선별·금지 출력·인용 주제·두 공급자 payload·미사용 GET·입력 예산.
- 실제 합성 HTTP 완료 흐름: 설문, 규칙전환, 약속 30문항, 기본/선택/조건부 면접을 저장한 후 회전/길/마법약 본게임도 실제 엔진으로 모두 완료. 보충13문항에 한국어 100자 이상씩 저장한 자료를 기본 종합 입력 예산으로 Gemini transport 대역에 1회 전달했다. 재생·수정 후 stale·확정 후 원문 고정·다른 계정 조회 차단도 검증했다.
- 프런트엔드는 합성 DOM에서 원문 프롬프트 보기, 명시적 요청, 근거 펼치기, stale 표시, 문자열 이스케이프를 확인한다.
- GPT-6.2 Astra high 독립 적대적 검토에서 기본 입력 한도 부족, 과거 후속 포함, 시각/라운드 맥락 누락, 숫자카드 WM 과잉연결, 불충분한 비교·출력 검증을 지적받아 수정했다.
- 전체 Python 511 passed, 전체 frontend 134 passed. 전체 검사 실행 도중 마친 마지막 입력 압축·비교 검증 변경은 이후 집중10개 검사로 재확인(15.68초)했다. 전체 검사 로그는 artifacts/synthesis-20261119/python-full.txt, frontend-full.txt. 실제 외부 AI와 브라우저 육안 평가는 미실행이다.
