# Codex 작업 명령: AI 역량검사 게임 3종 추가 구현

## 0. 프로젝트 목표

현재 개발 중인 AI 역량검사 웹사이트에 다음 게임 3종을 추가 구현하라.

1. 도형 회전하기 (공간지각능력)
2. 길 만들기 (계획능력)
3. 마법약 만들기 (학습능력 및 작업기억)

**단순한 시각적 목업이나 게임 화면만 제작하지 말고, 실제 사용자가 시작부터 종료까지 플레이하고 결과를 확인할 수 있도록 구현한다.**

작업을 시작하기 전에 반드시 현재 프로젝트의 코드 구조, 사용 기술, 기존 게임, 공통 점수 시스템, 게임 선택 화면, 결과 화면을 분석하라.

기존에 제작된 숫자 누르기, 정류장 기억하기, 약속 날짜 정하기, 가위바위보, 약속 장소 정하기의 기능은 변경하거나 삭제하지 않는다.

새 게임은 기존 프로젝트의 UI 디자인, 기술 스택, 코드 구조, 네비게이션 및 결과 저장 방식을 최대한 재사용한다.

## 1. 공통 구현 원칙

### 1-1. 공식 근거

아래 JOBDA 개발사의 공식 설명을 게임 규칙 및 평가 목적의 기준으로 삼는다.

- 전체 게임 설명: https://www.jobda.im/info/406
- 도형 회전하기: https://www.jobda.im/info/336
- 길 만들기: https://www.jobda.im/info/338
- 마법약 만들기: https://www.jobda.im/info/339

공식 자료에서 확인되는 사항은 실제 게임 동작에 반영한다.

반면 정확한 점수 산식, 시작 점수, 문항별 감점, 난이도별 가중치 등은 공개되지 않았으므로 임의로 JOBDA의 공식 규칙이라고 주장하지 않는다.

미확인 사항을 구현해야 한다면 '프로젝트 자체 설정'으로 명확하게 구분한다.

### 1-2. 공통 게임 진행 구조

각 게임은 다음 흐름으로 구성한다.

게임 선택 → 게임 설명 → 연습 문제 → 본 게임 → 문제 해결 → 다음 문제 → 최종 결과

공통 요구사항:

- 게임 시작 전 조작 방법을 안내한다.
- 연습 문제는 본 점수에 반영하지 않는다.
- 현재 문제 번호, 남은 시간, 남은 조작 횟수 등을 표시한다.
- 문제마다 중복 점수 지급을 방지한다.
- 게임 종료 후 획득 점수와 수행 지표를 보여준다.
- 새로고침 또는 화면 이동 시 기존 시스템의 정책에 맞춰 상태를 처리한다.
- 키보드와 마우스로 조작할 수 있도록 한다.
- 사용자 화면과 실제 판정 로직을 분리한다.

## 2. 게임 A: 도형 회전하기

### 2-1. 공식 평가 목적

**측정 역량: 공간지각능력**

도형의 회전과 반전을 이해하고, 목표 도형을 만들기 위해 공간적 관계를 파악하는 능력을 평가한다.

특히 도형을 정확하고 효율적으로 변환하는 과정에 중점을 둔다.

### 2-2. 게임 규칙

화면에 두 가지 도형을 표시한다.

- '전': 변환하기 전 원본 도형
- '후': 사용자가 만들어야 하는 목표 도형

사용자는 원본 도형을 회전하거나 반전해 목표 도형과 동일하게 만들어야 한다.

사용 가능한 명령은 다음과 같다.

- 왼쪽 45도 회전
- 오른쪽 45도 회전
- 좌우 반전
- 상하 반전

게임 진행 중에는 변환 명령만 기록하고, 명령을 입력할 때마다 완성된 도형을 직접 보여주지 않는다.

이렇게 해야 사용자가 머릿속으로 회전 및 반전 결과를 계산하도록 유도할 수 있다.

단, 튜토리얼에서는 변환 결과를 표시해 조작 방법을 학습할 수 있도록 한다.

### 2-3. 구현 요구사항

- 도형은 비대칭 다각형이나 비대칭 문자 형태를 사용한다.
- 회전과 반전은 실제 좌표 변환으로 구현한다.
- 명령을 적용하는 순서에 따라 결과가 정확하게 달라져야 한다.
- 도형의 초기 형태와 정답 목표 도형을 자동 생성할 수 있어야 한다.
- 모든 문제는 정답이 존재하도록 생성한다.
- 정답과 관계없이 불필요한 명령을 반복하는 문제를 방지한다.
- 실행 취소와 초기화 기능을 제공한다.
- 제출 시 사용자의 명령을 순서대로 적용하여 정답 여부를 판별한다.
- 도형의 형태와 위치를 비교할 때 부동소수점 오차를 고려한다.

### 2-4. 자체 게임 설정

다음 값은 JOBDA 공식 점수 규칙이 아니라 프로젝트 기본값이다.

- 문제 수: 10문항
- 전체 게임 시간: 240초
- 문제당 최대 변환 조작: 20회
- 정답: +10점
- 오답 또는 시간초과: -5점
- 시작 점수: 0점
- 최소 점수: 0점
- 최대 획득 점수: 100점

모든 값은 설정 파일에서 변경 가능하게 한다.

### 2-5. 추가로 기록할 평가 지표

단순 정답률 외에 다음 정보를 저장한다.

- 문항별 정답 여부
- 문제 해결 시간
- 실제 회전 및 반전 횟수
- 최소 필요 조작 횟수
- 실행 취소 횟수
- 초기화 횟수
- 조작 횟수 초과 여부

최소 조작 횟수는 BFS 등 상태 공간 탐색 알고리즘을 이용해 정확히 계산한다.

이를 통해 사용자의 실제 조작 횟수와 최소 필요 조작 횟수를 비교할 수 있도록 한다.

다만 조작 효율을 공식 JOBDA 점수로 환산하지는 않는다.

## 3. 게임 B: 길 만들기

### 3-1. 공식 평가 목적

**측정 역량: 계획능력**

주어진 목표를 달성하기 위해 불필요한 행동을 최소화하고 효율적으로 계획하는 능력을 평가한다.

특히 다음 두 가지에 중점을 둔다.

- 사용한 울타리의 개수
- 문제 해결에 사용한 클릭 횟수

### 3-2. 게임 규칙

격자 형태의 게임판에 교통수단과 목적지에 해당하는 손님이 등장한다.

사용자는 게임판에 울타리를 설치하여 각각의 교통수단이 지정된 손님에게 도착하도록 경로를 구성해야 한다.

교통수단은 일정한 방향으로 이동하며, 대각선 울타리에 부딪히면 진행 방향이 90도 변경된다.

서로 다른 교통수단의 이동 경로가 겹치는 것은 허용한다.

하나의 울타리를 여러 교통수단이 공유할 수 있어야 한다.

목표는 모든 교통수단을 올바른 목적지로 보내면서 설치 울타리 수와 조작 횟수를 최소화하는 것이다.

### 3-3. 구현 요구사항

- 기본 게임판은 5×5 격자를 사용한다.
- 격자의 크기는 설정으로 변경할 수 있도록 한다.
- 각 교통수단은 출발 위치, 진행 방향, 목표 위치를 가진다.
- 사용자는 격자에 '/' 또는 '\' 형태의 대각선 울타리를 설치할 수 있다.
- 울타리의 방향에 따라 진행 방향을 90도 변경한다.
- 울타리 설치, 방향 변경, 제거 기능을 제공한다.
- 제출 버튼을 누르면 교통수단의 이동을 시뮬레이션한다.
- 교통수단이 올바른 손님에게 도착해야 성공으로 인정한다.
- 목적지가 틀리거나 게임판을 벗어나면 실패 처리한다.
- 같은 위치와 진행 방향이 반복되는 경우 무한 루프로 판정한다.
- 교통수단마다 구별 가능한 색상과 표시를 사용한다.
- 경로가 겹쳐도 게임 로직이 정상적으로 동작해야 한다.

교통수단의 이동 시뮬레이션은 상태 전이 로직으로 구현하고, 실제로 모든 교통수단을 성공시킬 수 있는 문제만 제공한다.

### 3-4. 문제 생성

문제를 생성할 때 다음 조건을 만족해야 한다.

- 해결 가능한 문제여야 한다.
- 정답이 존재해야 한다.
- 최소 울타리 개수를 계산하거나 검증할 수 있어야 한다.
- 지나치게 단순하거나 불가능한 문제가 나오지 않아야 한다.
- 난이도에 따라 교통수단 수와 경로 복잡도를 조절한다.

자동 생성이 불안정하다면 검증된 고정 문제 데이터를 먼저 구현하고, 이후 확장 가능한 생성기 구조를 작성한다.

### 3-5. 자체 점수 설정

- 문제 수: 10문항
- 전체 게임 시간: 240초
- 문제당 최대 조작 횟수: 19회
- 모든 교통수단의 목표 도착: +10점
- 잘못된 제출 또는 시간초과: -5점
- 시작 점수: 0점
- 최소 점수: 0점
- 최대 획득 점수: 100점

이 값은 프로젝트의 자체 배점이다.

문항당 점수 적용은 한 번만 하며, 조작 중 단순히 울타리를 설치하거나 제거했다는 이유로 추가 감점하지 않는다.

### 3-6. 추가 평가 지표

- 사용한 울타리 개수
- 최적 울타리 개수
- 총 조작 횟수
- 울타리 변경 및 제거 횟수
- 최초 조작까지 걸린 시간
- 문제 해결 시간
- 정답 및 실패 여부
- 교통수단별 목적지 도착 여부

사용자가 문제를 맞혔더라도 최적 울타리 개수보다 많은 울타리를 사용했다면 효율성 지표에서 그 차이를 확인할 수 있도록 한다.

## 4. 게임 C: 마법약 만들기

### 4-1. 공식 평가 목적

**측정 역량: 학습능력, 작업기억**

이 게임은 도형 회전하기와 길 만들기처럼 매번 확정적인 정답이 존재하는 게임이 아니다.

과거 결과를 학습하고, 카드 조합에 따라 어떤 결과가 나타날 가능성이 높은지 예측하는 능력을 평가한다.

확률적인 학습 과제이므로 모든 문제에서 예측을 적중시키는 것은 불가능할 수 있다.

### 4-2. 게임 규칙

화면에는 4개의 재료 카드가 제시된다.

사용자는 카드들의 재료 조합을 보고 다음 중 한 가지를 선택한다.

- 빨간약
- 파란약

각 카드 조합에는 빨간약 또는 파란약이 만들어질 확률이 존재한다.

예를 들어 어떤 조합에서 빨간약 생성 확률이 80%, 파란약 생성 확률이 20%일 수 있다.

그러나 응시자에게 이러한 확률을 직접 보여주지 않는다.

응시자는 반복 시행에서 나타나는 결과를 학습해 더 가능성이 높은 색상을 선택해야 한다.

같은 카드 조합에서도 이전과 다른 결과가 발생할 수 있어야 한다.

### 4-3. 구현 요구사항

- 화면에 4개의 재료 카드를 표시한다.
- 각 조합에는 고정된 내부 확률을 설정한다.
- 내부 확률은 게임 중 사용자에게 공개하지 않는다.
- 사용자가 빨간약 또는 파란약을 선택하면 확률에 따라 실제 제조 결과를 결정한다.
- 결과를 보여준 후 다음 문제로 넘어간다.
- 동일한 조합을 여러 번 제시해 사용자가 경험을 바탕으로 학습하도록 한다.
- 카드의 순서가 아닌 전체 조합을 기준으로 확률을 관리한다.
- 특정 재료 하나로 결과를 항상 정확하게 예측할 수 없게 한다.
- 확률에 따라 같은 조합에서 서로 다른 결과가 발생해야 한다.
- 사용자가 과거 결과를 학습할 수 있도록 문제별 피드백을 제공한다.

### 4-4. 확률 설정

실제 JOBDA의 카드 조합별 확률은 공개되지 않았으므로 자체 확률 모델을 사용한다.

예시:

| 조합 | 빨간약 확률 | 파란약 확률 |
|---|---:|---:|
| A | 80% | 20% |
| B | 20% | 80% |
| C | 65% | 35% |
| D | 35% | 65% |
| E | 70% | 30% |
| F | 30% | 70% |

위 확률은 자체 설계 예시이며 공식 수치가 아니다.

문제마다 확률을 새로 생성하지 말고, 동일한 조합에는 게임 세션 내에서 동일한 확률을 유지한다.

무작위 결과는 재현 가능한 난수 시드로 생성할 수 있도록 한다.

### 4-5. 자체 점수 설정

- 새 본게임 문제 수: 48문항. 이전에 시작한 100문항 시도는 시작할 때 저장한 문항 수를 따른다.
- 빠른 연습 모드: 20문항
- 정답 또는 예측 적중: +10점
- 예측 실패 또는 시간초과: -5점
- 시작 점수: 0점
- 최소 점수: 0점
- 48문항 기준 최대 획득 점수: 480점

단, 이 점수는 프로젝트의 게임화 점수이며 실제 학습능력의 검증된 점수가 아니다.

마법약 만들기는 확률적 결과를 사용하므로 동일한 판단을 하더라도 운에 따라 적중 수가 달라질 수 있다는 점을 반드시 고려한다.

### 4-6. 별도 학습 지표

단순 적중률뿐 아니라 다음 정보를 저장한다.

- 전체 예측 적중률
- 조합별 선택 횟수
- 조합별 빨간약·파란약 선택 비율
- 실제 생성 결과
- 문제별 반응시간
- 초기 구간과 후기 구간의 선택 변화
- 확률적으로 유리한 색상을 선택한 비율
- 관측 결과를 바탕으로 선택을 수정하는 패턴

특히 **실제 생성된 색상과 확률적으로 더 유리한 색상은 구분**해야 한다.

예를 들어 빨간약 확률이 80%인 조합에서 사용자가 빨간약을 선택했지만 실제로 파란약이 생성되었다면, 예측은 실패했어도 확률적으로는 유리한 판단을 한 것이다.

따라서 결과에는 '예측 적중률'과 '확률적으로 유리한 선택 비율'을 별도로 제공한다.

## 5. 공통 점수 시스템

우선 현재 프로젝트의 기존 점수 시스템을 확인한다.

기존 게임이 다음 배점을 사용하고 있다면 동일하게 적용한다.

- 시작 점수: 0점
- 정답: +10점
- 오답: -5점
- 시간초과: -5점
- 최소 점수: 0점

점수 갱신 규칙:

`newScore = Math.max(0, currentScore + delta)`

매 문항 종료 시 한 번만 점수를 갱신한다.

이 방식은 점수를 매번 0점 이상으로 제한하므로 정답과 오답의 순서에 따라 최종 점수가 달라질 수 있다. 이 동작을 명시적으로 유지하고 테스트하라.

기존 프로젝트에서 다른 점수 규칙을 사용하고 있다면 기존 시스템을 우선 분석하고 차이점을 보고하라. 임의로 기존 게임의 점수 로직을 변경하지 않는다.

문항별 최대 점수는 +10점으로 계산하고, 게임별 만점은 문항 수 × 10점으로 설정한다.

서로 다른 문제 수를 가진 게임을 종합 결과에서 비교할 때는 원점수 외에 0~100점으로 환산한 표시 점수를 별도로 제공한다. 단, 이것은 자체 게임 점수의 정규화일 뿐 심리측정 점수나 백분위가 아니다.

점수 설정과 행동 지표는 각각 별도로 관리한다.

## 6. 평가 결과 화면

각 게임 종료 후 다음 정보를 출력한다.

**공통 결과**

- 게임 이름
- 평가 대상 역량
- 총 문제 수
- 정답 또는 예측 적중 수
- 오답 수
- 시간초과 수
- 최종 점수
- 최대 가능 점수
- 평균 반응시간

**게임별 추가 결과**

도형 회전하기:
- 공간지각 관련 과제 수행 결과
- 최소 조작 횟수 대비 실제 조작 횟수
- 조작 효율성

길 만들기:
- 계획능력 관련 과제 수행 결과
- 최적 울타리 수 대비 실제 사용량
- 평균 조작 횟수

마법약 만들기:
- 학습능력 관련 과제 수행 결과
- 초기·후기 선택 패턴 변화
- 조합별 학습 결과
- 예측 적중률과 확률적으로 유리한 선택 비율

주의 사항:

이 게임들만으로 응시자의 정직성, 거짓말 여부, 실제 업무 성과나 직무 적합성을 확정적으로 판정하지 않는다.

결과 화면에는 '이 결과는 자체 제작 게임의 수행 지표이며, 표준화된 심리검사 점수가 아닙니다'라는 안내를 포함한다.

## 7. 기술적 구현 지침

1. 기존 프로젝트에서 사용하는 프레임워크와 언어를 유지한다.
2. 기존 컴포넌트 및 스타일을 가능한 범위에서 재사용한다.
3. 게임 로직, 화면 렌더링, 문제 생성기, 채점 로직을 분리한다.
4. 세 게임을 각각 독립적인 모듈로 구현한다.
5. 게임별 설정은 별도의 Config 객체 또는 파일로 관리한다.
6. 점수·시간·문제 진행 상태가 서로 충돌하지 않도록 한다.
7. 이미 종료된 문항에서 중복 제출이나 중복 점수 갱신이 발생하지 않도록 한다.
8. 기존 게임 선택 메뉴에 새 게임 3종을 추가한다.
9. 기존 결과 저장 구조와 통합한다.
10. 기존 게임과 새 게임이 모두 정상 작동하도록 유지한다.

임의의 이미지나 장식적인 화면만 만들고 기능 구현을 생략하지 않는다.

공식 게임의 로고와 이미지 자산을 무단 복제하지 말고, 동일한 학습 목적을 가진 독자적인 시각 디자인으로 구현한다.

## 8. 테스트 및 검증

각 게임에 대해 자동 테스트를 작성한다.

**도형 회전하기**

- 45도 회전 정확성
- 좌우·상하 반전 정확성
- 조작 순서에 따른 결과 변화
- 정답 및 오답 판정
- 조작 제한
- 실행 취소와 초기화
- 생성한 모든 문제의 해결 가능성

**길 만들기**

- 울타리별 방향 변경
- 잘못된 경로 및 게임판 이탈
- 반복 상태의 무한 루프 탐지
- 여러 교통수단의 경로 공유
- 모든 목적지 도착 검증
- 최소 울타리 수 검증
- 조작 횟수 제한

**마법약 만들기**

- 확률의 합이 100%인지 확인
- 동일 조합의 확률 유지
- 난수 시드 기반 결과 재현
- 조합별 결과가 확률적으로 발생하는지 검증
- 문제별 정답 처리와 점수 계산
- 학습 지표 계산 정확성

세 게임 모두 시작, 중단, 재시작, 종료, 시간초과, 결과 화면 전환을 실제로 테스트한다.

기존 프로젝트에 테스트·빌드·린트 도구가 있다면 해당 명령을 실행한다.

## 9. 최종 작업 결과 보고

구현을 완료한 후 다음 내용을 보고하라.

1. 현재 프로젝트 구조에서 어떤 부분을 분석했는가?
2. 새로 추가하거나 수정한 파일은 무엇인가?
3. 각 게임의 규칙과 실제 구현 방식은 무엇인가?
4. 점수의 시작값, 만점, 정답 가점, 오답 감점은 어떻게 적용했는가?
5. 게임별 평가 지표는 어디에 저장되는가?
6. 테스트 결과는 어떠한가?
7. 아직 미구현 또는 검증되지 않은 기능은 무엇인가?
8. 공식 JOBDA 규칙과 자체 구현 규칙의 차이점은 무엇인가?

**중요:**

설계 문서나 구현 계획만 작성하고 종료하지 말고, 실제로 실행 가능한 게임을 구현하라.

세 게임 모두 사용자가 직접 플레이하고 결과를 확인할 수 있어야 한다.

작업 도중 구조적 문제가 발견되면 기존 코드를 최대한 보존하는 방식으로 해결하라.

공식적으로 공개되지 않은 채점 방법은 임의로 만들어 공식 점수라고 설명하지 마라.
